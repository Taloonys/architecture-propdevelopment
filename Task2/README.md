# System Reasons
* Есть несколько точек регистрации клиента, они и работа с их данными не согласованы
* Контракты API содержат персональную информацию, также их можно подделать
* Клиенты могут случайно получить доступ к информации других клиентов
# Solving
> Основываясь на проблемах компании, стоит задуматься о следующих категориях в чек-листе:
* Управление доступом - основным моментом для подобного раздела стали инцеденты с тем, что пользователи могут получить информацию о других пользователях, а также разработчики одной компании партнёры могут получить доступ к состоянию системы другого партнёра. Ситуация с пользователями особенно остро влияет на UX и репутацию компании.
* Безопасность данных - проблемы с контрактами API ведут к проблеме с утечками данных, возможностями подделать сами транзакции или их историю, что усложняет категорию исследования инцедентов. Сама по себе утечка конфиденциальных данных ведёт ещё и к проблемам с законом, помимо очередных репутационных рисков.
* (Опционально) Управление инцедентами - связано с формированием ландшафта решений по безопасности данных, раз уж столь явные проблемы присутствуют, следует также определить с "наблюдаемостью" решений безопасности.
> В задании указано, какие категории включить, по-хорошему же вроде все категории и вопросы должны обговариться... Но по заданию как будто достаточно самые основные категории учитывать.
